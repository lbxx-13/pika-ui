# 设计方向与方向卡

只有方向尚未确定、新项目缺少视觉规则、用户要求重新探索或对现有方向不满意时才读。用户给定方向、品牌规范或截图还原任务时，不重起概念。

## 先写产品事实

从项目和请求里整理用户、任务、真实内容、场景、主设备、品牌、已有素材、实现限制和交付形式。未知项标为未知，不把参考产品的功能或数据写成 Pika UI 的事实。

锁定首屏/关键状态的唯一主角和主动作。次要动作要么删除，要么降级，并确定主动作会带来什么对象变化和反馈。

## 参考与取舍

只有需要同类产品参考时，才寻找两三个有区分度的产品；用真实页面或录屏作为证据，不靠对产品的模糊印象。每个观察写“具体选择 + 它服务的内容/用户/场景”。产品视觉参考与交互参考分开记录：交互按“触发 → 对象变化 → 反馈 → 下一状态”拆解。

三种关系要分清：

- **品类基线：** 用户已熟悉的结构，沿用可降低学习成本。
- **品类套路：** 普遍的默认版式，可以评估是否改善，但改变前要有产品理由。
- **撞脸：** 多项核心视觉和参考过于接近，只替换品牌名；需要重选差异来源。

## 把调性落到画面

用产品证据判断以下方向，不必追求每个轴都走到极端：

| 轴 | 画面依据 |
| --- | --- |
| 能量：安静—喧闹 | 饱和度、对比、元素碰撞 |
| 完成度：粗粝—精致 | 边缘、颗粒、对齐公差 |
| 密度：疏—密 | 留白、信息量、叠层 |
| 分量：轻—重 | 字重、色块面积、阴影硬度 |
| 严肃度：活泼—庄重 | 圆角、图形语气、动效幅度 |

“高级、简洁、克制、冲击力”等词必须翻译成具体选择：字体对比、色相/饱和度预算、主视觉面积、密度、动效幅度或要删掉的重复信息。翻译不了，就不把形容词当设计理由。

## 方向卡

每个方向写清：

1. 名称与一句概念；
2. 主角、主动作和关键状态；
3. 首屏骨架与阅读顺序；
4. 字体层级与来源；
5. 底色、强调色和状态色的用途及来源；
6. 主视觉/媒体的来源；
7. 关键动效及其体验目的；
8. 依赖、素材或性能风险。

先画灰度结构，确认主角、主动作和阅读顺序，再补视觉语言。灰度结构相同的方案不能靠换色冒充不同方向。多个方向的差别来自产品依据；不要为了“一个亮、一个暗、一个暖”而凑数。

## 色彩

品牌资产、真实产品内容和用户提供的素材优先作为颜色来源。没有主色时，避免直接把概念材质（如木头、黄铜）自动变成全站主色。定义底色、文字色、强调色，以及选中、描边、禁用和状态色如何派生；确保颜色不是状态的唯一线索。黑白灰加一种强调色，或由真实图片承载色彩，都可以成为完整方案。
