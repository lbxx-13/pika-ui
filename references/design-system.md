# 设计系统维护

用于现有规范彼此冲突、文档和代码不一致，或需要从页面沉淀可复用规则的任务。

## 先盘点，不先改写

只检查当前范围相关的规范文件、主题变量、共用组件和实际页面。记录：

- 文件/代码位置与适用范围；
- 同一概念的重复或冲突定义（如品牌色、圆角、字体、间距）；
- 页面实际使用情况与明确偏离；
- 哪些决定会改变本次任务的视觉或行为。

规范文件和实现冲突时，以用户明确指定的权威来源为准。没有指定时，列出冲突和建议取舍；不要悄悄合并、删除或全局重写规范。当前页面任务可以先按已确认约束完成，并在交付说明中标出未决项。

## 沉淀新规则

只记录已在真实页面验证并且确实会复用的规则。优先包含颜色语义、字体角色、间距/圆角尺度、组件状态、断点行为和动效原则。例子使用项目真实组件或内容，避免另造第二套 tokens。

每项规则写清用途和例外边界；页面特例留在页面文档，不升级成全局规范。修改前说明涉及范围，修改后检查使用该规则的代表页面。
