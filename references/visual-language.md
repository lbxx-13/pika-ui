# Pika UI 视觉语言

本指南帮助把方向变成可复用、可落地的视觉规则。它不预设 Pika UI 的品牌色、字体或产品类型：先检查项目现有 token 和品牌资产；若项目没有，就为本次界面建立一组简洁规则，并沿用到所有相关页面。

## 页面构图与层级

- 每屏设定一个主焦点。用户进入页面后，应能迅速分辨页面标题/任务、主要内容和首要操作。
- 内容宽度根据阅读任务决定：长文本使用较窄的阅读列；仪表盘和编辑器依据工作区内容安排侧栏与主区。
- 间距按少量尺度递进，使用更大的间隔区分章节，使用较小间隔表达组件内部关系。避免相邻组件随机取值。
- 对齐优先于装饰。明确页面主轴、文字边缘、控件基线和网格；只有层级或关系需要时才加分割线。
- 同组靠近、组间拉开；先用空间区分，再调字号/字重和底色，最后才考虑边框。父布局负责区域间距，组件负责内部间距，避免重复叠加。
- 用连续排版、图片和留白表达内容关系；不要为了统一而把全部内容切成同样的卡片。

## 字体与内容

- 从项目已有字体开始。按语义定义标题、正文、辅助说明、控件标签和数字的层级，不要每个模块单独挑字号。
- 中文正文优先保证清晰的字号与行高；英文缩写、数字、日期和价格要检查字宽、基线与字体回退。
- 标题优先短而具体。长标题测试窄屏折行；正文行宽适合阅读；表格数据保持列对齐。
- 区分有意的弱化文字与不可读的浅灰字。辅助信息可以低权重，但不能因为颜色太淡而消失。
- 在真实视口与实际字体下判断字号；缩略图只能看构图。中文正文可从 14–16px 起步，长阅读从 16–18px 起步，高密度工具在确有需要时可到 13–14px；正文行高通常从 1.6–1.75 起步。这些是检查起点，不是跨产品的固定指标。
- 多行中文标题可从 1.2–1.35 行高起步。检查数字单位、不可拆词、中英混排、长标题和窄屏孤字；先调整容器高度与行高，不靠缩小字号解决碰撞。
- 重要名称和说明避免固定高度裁切。确需截断时提供查看完整内容的入口，并确保相似名称仍可区分。

## 颜色与表面

- 先定义页面背景、主文字、次级文字、边界/分隔、品牌强调、成功、警告和错误的用途，再选颜色值。
- 强调色用于操作或关键状态，确保它在页面中有稳定含义；不要把所有标题、图标和边框都染成品牌色。
- 检查文本/背景、按钮/底色、边界/背景和焦点环的对比。不要仅靠颜色区分状态。
- 圆角、阴影、描边和透明度用于说明层级、可点击性或浮层关系。一个界面里保持一致，避免多层容器同时使用重阴影。
- 深色模式若没有明确要求，不要为了“科技感”默认采用；若项目已有主题机制，使用现有语义 token。

## 图像、图标与动效

- 选图服务于语境、可信度或内容识别。优先使用用户/项目真实资产，检查图像裁切和色温一致性。
- 图标沿用项目已有图标库和线宽。无图标语义时配合文字标签，不用 emoji 假装功能图标。
- 进入、反馈和状态变化用短而明确的动效。避免连续无目的漂浮、自动播放背景和大面积运动干扰阅读。
- 复杂动效可参考 React Bits 的示例，但它不是跨平台组件库；先理解交互、性能和可访问性边界，再按目标平台实现。React 以外的项目不要直接复制 React 组件。

## 最终一致性

把复用规则沉淀为项目已有 token 或变量，不创建与已有系统竞争的新命名。如果本次确实建立了新规则，在相关组件中统一使用，并在交付说明里指出规则文件位置。方向的独特性来自构图、内容和视觉焦点协同，不是单靠调色。
