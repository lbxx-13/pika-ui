# 动效设计与 React Bits

动效解释操作、状态与层级。先定义用户动作和对象变化，再选动画；不要先挑特效再寻找放置位置。

## 先设计三处关键反馈

对新界面或本次改变了流程的界面，先确认：

1. **主操作反馈：** 按下立即有响应，完成时给出可见结果，例如按钮状态、勾选或结果数字变化。
2. **状态切换：** 选中、展开、视图切换或列表增删时，让用户看出变化从哪里来、到哪里去。
3. **首次进入：** 需要时让页面主角先进入，其他内容按阅读顺序跟上；只在首次进入播放。

这三处无需都使用复杂动画。高频操作保持短促，品牌时刻才考虑较长演出；没有产品专属巧思时，把基础反馈做清楚就够了。

## 选择实现方式

| 需求 | 优先考虑 |
| --- | --- |
| hover、focus、按下、简单展开 | CSS transition 或项目已有组件 |
| 视图转换、元素换位 | 项目现有动效方案；保持来源、方向与结果连续 |
| 拖拽、手势、弹簧、多物件协同 | 已有成熟动效库或专用组件 |
| 复杂材质、粒子、着色器或 3D | React Bits 对应组件或静态/预渲染方案，并评估性能与回退 |
| 实时数据或用户要操作的控件 | 必须使用真实状态驱动的代码，不能用视频冒充可操作界面 |

集成 React Bits 前按 [React Bits 指南](react-bits.md) 预览效果并检查依赖。组件的默认演示参数不是设计结论；需要对照页面方向调速度、幅度、密度、色彩和触发方式。

## 过渡与连贯性

- 动画从触发动作或被操作对象出发；连续的变化沿同一方向接续。按钮、面板和数字不要彼此无关地同时跳动。
- 内容不变、只换位置或尺寸时优先让同一对象变形；内容真正替换时才做淡入/淡出。
- 列表移除、加入和保留分别处理：移除项离场，新项入场，保留项移动到新位置。
- 打开和关闭、进入和返回应互为逆过程；方向与空间位置保持一致。
- 视图切换的目标内容提前准备好，避免转场落在白屏或加载空洞上。加载较慢时先呈现稳定的加载状态，再显示内容。

## 可访问性与性能

- 内容不能依赖动画才可见；尊重 `prefers-reduced-motion`，减少或取消非必要位移、视差和循环动效。
- 动效不应抢焦点、阻止键盘操作、造成页面滚动锁死或遮住主操作；触屏上给出等价反馈。
- 避免无意义持续循环、多个大面积动画同时运行和高频昂贵渲染。对 Canvas/WebGL/粒子效果检查低性能设备与不可用时的静态回退。
- 录屏或关键帧只能辅助检查；最终要在真实页面操作，确认动画与状态更新一致。
